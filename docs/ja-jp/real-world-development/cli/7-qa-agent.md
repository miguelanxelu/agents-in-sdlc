これまでに `quality-checks` スキルで自動チェックを実行し、Playwright MCP でブラウザー上のフィルター機能を確認しました。ここでは、それらの機能を明確な QA プロセスを持つカスタムエージェントにまとめます。

このレッスンでは、次の作業を行います。

- カスタムエージェントが指示、スキル、MCP ツールとどのように連携するかを確認します。
- 再利用できる品質保証プロファイルを作成して調べます。
- QA エージェントを選択し、フィルター機能の issue に照らして結果をレビューします。

## シナリオ

Tailspin Toys では、プルリクエスト (PR) を作成する前に、要件、コード品質、自動チェック、テスト範囲、ブラウザーでの動作を一貫した方法でレビューしたいと考えています。カスタムエージェントを使うと、この QA プロセスを調整し、再利用できるレポートを作成できます。

## カスタムエージェントとは

カスタムエージェントは、Markdown プロファイルで定義する、専門化された Copilot です。プロファイルにエージェントの目的、指示、使用できるツールを記述します。このワークショップでは `.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまでに使ったカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を定めます。`quality-checks` スキルは繰り返し実行できるチェックをまとめます。Playwright MCP はブラウザー操作ツールを提供します。QA プロファイルは、それらを使って要件を評価し、結果を報告する方法を Copilot に指示します。これらの機能を置き換えるものではなく、別の会話も必要ありません。

## QA プロファイルを作成する

機能の PR を作成する前に、再利用できる QA プロファイルを Copilot に作成してもらいます。プロファイルには、QA で実行するチェックと守るべき範囲の両方を定義します。

1. Codespace に戻り、フィルター機能の会話が Interactive モードであることを確認します。
2. 既定のエージェントに、次のカスタムエージェントを作成するよう依頼します。

   ```plaintext
   `.github/agents/qa.agent.md` に QA という名前のカスタムエージェントを作成してください。機能を issue と合意済みの要件に照らして確認し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP を使って動作を検証し、テスト範囲が不足している場合はテストを追加してください。

   各要件について、根拠を示しながら pass、fail、blocked のいずれかで報告させてください。実装コードを変更する前に必ず確認を求め、変更をコミットしたりプルリクエストを作成したりしないようにしてください。

   今はレビューできるようにプロファイルだけを作成してください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、Copilot が意図した QA の流れと制約をプロファイルに反映したことを確認します。これにより、検証だけを依頼したのに不完全または広範囲すぎるエージェントが機能を変更するのを防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. フロントマターを読みます。`description` は必須です。`name` は任意ですが、含めるとエージェントの表示名が明確になります。
3. プロファイルの指示を読み、QA が要件を起点とし、リポジトリの指示に従い、`quality-checks` スキルを実行して Playwright MCP を使うことを確認します。
4. QA が根拠を示して報告し、実装コードを変更する前に確認を求め、変更をコミットせず、プルリクエストも作成しないことを確認します。
5. これらの責務や制約が抜けている場合は、続行する前に既定のエージェントへ修正を依頼します。

## issue を基に QA を実行する

Copilot CLI は会話の開始時にプロジェクトのエージェントを読み込みます。プロファイルを作成した後、同じフィルター機能の会話を再開して QA を選択すると、issue と計画時の決定事項を引き継いで利用できます。

1. 次のプロンプトを入力してエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> エージェントを作成した直後は、利用可能なエージェントの一覧に表示されない場合があります。次のコマンドで有効にできます。

2. 次のプロンプトで、QA エージェントに機能をレビューするよう依頼します。

   ```plaintext
   フィルター機能を issue と計画時の決定事項に照らしてレビューしてください。PR を作成できる状態ですか。
   ```

3. QA エージェントが作業を進めるのを待ちます。
4. 完了したら、エージェントのレポートを読みます。

- 再利用できる品質保証プロファイルを作成して調べました。
- QA エージェントを選び、フィルター機能の issue に照らして結果をレビューしました。
