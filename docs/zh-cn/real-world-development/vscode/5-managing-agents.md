使用 GitHub Copilot 智能体模式时，它会自主探索代码库、提出更改、编辑文件并运行命令。由于 Copilot Chat 在本地实时执行这些工作，VS Code 会显示每次工具调用和文件编辑。你可以在聊天中审查每个差异、接受或拒绝单项更改，并通过后续提示引导对话、完善或扩展工作，全程无需离开编辑器。

在本课中，你将：

- 实时监控无障碍访问智能体的工作。
- 审查并接受建议的文件编辑。
- 在会话进行时引导智能体，同时添加浅色模式切换。

## 场景

你在[练习 4][previous-lesson]中使用的无障碍访问自定义智能体正在实现高对比度模式。工作进行期间，设计团队提出了额外需求：他们也希望为觉得默认主题过暗的用户添加浅色模式切换。你将继续引导现有会话扩展工作，而不是从头开始新对话。

## 监控 Copilot 的进度

Copilot Chat 视图会显示智能体执行的每个步骤，包括探索的文件、运行的命令和提出的编辑。每项文件编辑都会以内联差异的形式显示，并提供 **Keep** 和 **Undo** 控件。

1. 返回练习 4 中使用的 Copilot Chat 视图。
2. 智能体工作时，滚动聊天内容，查看工具调用。你会看到文件读取、文件编辑以及需要运行的终端命令。
3. 智能体提出文件编辑时，差异会以内联方式显示：
   - 选择 **Keep** 接受更改。
   - 选择 **Undo** 撤销更改，让智能体重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看智能体在此会话中修改的完整文件列表。

> [!NOTE]
> 如果工具调用请求权限（例如运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准你认可的命令。

5. 等待智能体完成高对比度模式。完成后应会显示总结其更改的最终消息。

## 引导智能体添加浅色模式

高对比度模式完成后，继续使用同一对话添加浅色模式切换。由于继续使用同一会话，智能体会保留之前工作的上下文，包括已修改的组件、样式方法和本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得不错！现在在高对比度切换旁添加浅色模式切换。浅色模式应采用相同模式：通过本地存储保留设置，并且可从界面的同一区域访问。用户应能分别启用高对比度模式和浅色模式。
    ```

2. 智能体会继续之前的工作，探索已有更改并提出浅色模式相关修改。
3. 像审查高对比度模式一样，逐项审查新编辑，并使用 **Keep** 或 **Undo**。
4. 如果智能体的处理方向不符合预期，例如以你不喜欢的方式重构切换用户界面（UI），可以选择聊天输入框旁的 **Stop** 按钮停止任务，然后发送澄清提示。

> [!TIP]
> 引导进行中的会话比从头开始更快。可以使用后续提示要求调整（“简化 CSS，改用 CSS 变量，避免重复选择器”）、纠正方向（“不要添加第三个切换开关，把浅色模式整合到现有设置面板中”）或扩展范围（“还要为两个切换开关添加键盘快捷键”）。

## 审查工作集

提交工作前，快速检查智能体修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 审查已更改文件的完整列表。应能看到 Astro 组件、样式和相关测试的更新。
3. 打开几个已更改文件并查看差异。确认其中体现了自定义智能体要求的无障碍访问模式，包括无障碍富互联网应用程序（ARIA）属性、键盘导航、语义化超文本标记语言（HTML）和本地存储。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课将发布这些更改。

## 总结和后续步骤

你已使用 Copilot Chat 智能体模式监控并引导进行中的会话：逐项审查文件编辑、接受或拒绝更改，并通过后续提示扩展工作，同时保留上下文。

本课介绍了以下内容：

- 实时监控智能体工作。
- 接受或拒绝单项文件编辑。
- 使用后续提示引导进行中的会话。
