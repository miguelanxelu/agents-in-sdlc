GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat では、自分のコンピューター上で行われる作業について、ツール呼び出しやファイル編集をリアルタイムで確認できます。差分をインラインでレビューし、変更ごとに採用または却下し、エディターを離れずに追加プロンプトを送って会話の方向を調整できます。

この演習では、次の作業を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- 同じセッションでハイコントラストに加えてライトモードも実装するよう、エージェントの方向を調整します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。新しい会話を一から始めず、既存のセッションをガイドして機能を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などの各手順が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともに Chat 内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、Chat をスクロールしてツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルを編集すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を元に戻し、別の方法を試すようエージェントに任せます。
4. Chat 上部の **Files changed** を開き、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に、変更内容の概要が表示されます。

## ライトモードを追加するようエージェントを調整する

ハイコントラストモードを実装したら、同じ会話でライトモードの切り替えを追加します。同じ Chat セッションを続けるため、エージェントは以前の作業、変更したコンポーネント、スタイルの方法、設定した local storage のパターンをコンテキストとして保持します。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   よくできました。次に、ハイコントラストの切り替えに加えてライトモードの切り替えも追加してください。ライトモードも同じ方法で実装し、local storage で設定を保持して、UI の同じ場所から操作できるようにしてください。ハイコントラストとライトモードは個別に有効にできるようにしてください。
   ```

2. エージェントがこれまでの変更を調べ、ライトモードの追加を提案することを確認します。
3. 新しい編集を1つずつレビューし、ハイコントラストモードのときと同じように **Keep** または **Undo** を選びます。
4. エージェントの方針が希望と異なる場合 (たとえば、トグル UI を意図しない方法でリファクタリングする場合) は、Chat 入力欄の横にある **Stop** ボタンで停止し、補足のプロンプトを送ります。

> [!TIP]
> 進行中のセッションを調整する方が、最初からやり直すより効率的です。追加のプロンプトを使って変更を依頼します (「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」)、方針を修正します (「3つ目のトグルを追加せず、ライトモードを既存の設定パネルに組み込む」)、または範囲を広げます (「両方のトグルにキーボードショートカットも追加する」)。

## 作業内容を確認する

変更をコミットする前に、エージェントが触れた内容をまとめて確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターンが反映されていることを確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持などが対象です。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、方向を調整しました。各ファイルの編集を確認し、変更を採用または却下し、コンテキストを保ったまま追加プロンプトで作業を広げました。

この演習では、次の作業を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または却下しました。
- 追加プロンプトを使い、進行中のセッションを調整しました。

[次のレッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このワークショップでローカルのカスタムエージェントが作成した変更をレビューします。
