フィルター機能の実装、指示の更新、スキルの更新、品質保証 (QA) プロファイル、テストは、1つのブランチに保存されています。まとめてレビューし、プルリクエストを作成します。星評価のプルリクエスト (PR) は自分でマージしました。今回は **Agent Merge** に進行を任せます。

> [!NOTE]
> 通常は、機能、指示の更新、スキルの更新、QA エージェントを複数の PR に分けます。ワークショップに集中できるよう、フィルター機能と品質改善の作業全体を同じセッションとブランチで進め、1つの PR にまとめています。

このレッスンでは、次の作業を行います。

- Agent Merge と、マージまでの流れを自動化する方法を確認します。
- 機能の PR 全体と検証の証拠を調べます。
- レビュー後にのみ Agent Merge を許可し、PR がマージされたことを確認します。

## シナリオ

フィルター機能のワークフローでは、Copilot を使って機能を計画、実装、検証しました。Tailspin Toys では、マージの承認権限は開発者が保持したまま、残りの PR 作業を自動化したいと考えています。

## Agent Merge について

**Agent Merge** は、GitHub Copilot app でプルリクエストを取り込むために必要な残りの作業を自動化します。有効にすると、アプリのセッションが PR を読み取り、継続的インテグレーション (CI) チェックの失敗を修正し、レビューコメントに対応し、必要に応じてリベースするなど、マージを妨げている問題に対処します。GitHub が許可するとマージします。バックグラウンドで実行され、アプリを再起動しても続き、PR がマージされると自動的に停止します。

ここまでは、自分で **Merge pull request** を選択していました。Agent Merge にその作業を任せることもできます。ただし、コードの編集とマージには、引き続き開発者による明示的な許可が必要です。マージを許可する前に、許可される操作と作業内容を確認してください。

## Agent Merge で PR を管理する

コードの作成とレビューが終わったら、Agent Merge に PR の処理を任せます。

1. エージェントピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択して処理を開始します。ドロップダウンの項目を選ぶだけでは開始されません。

Agent Merge が動作を開始し、次の処理を行います。

- タイトルと説明を含むプルリクエストを作成します。
- issue からセッションを開始した場合は、説明本文で関連する issue を参照します。
- ターゲットブランチにリベースするか、マージ競合に対処します。
- CI を監視し、すべてのチェックが成功することを確認します。
- 他の開発者や Copilot code review からのフィードバックを確認し、コメントを解決するよう更新します。
- 必要に応じて、すべての処理が成功した後に PR を自動的にマージします。

すべてのチェックが成功した後に PR もマージするよう、Agent Merge に許可を与えます。

5. マージを許可する前に、PR の差分と検証の証拠をレビューします。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** の横にチェックが付いていることを確認します。
8. 次のプロンプトを送信し、マージを明示的に依頼します。

   ```plaintext
   必須チェックと承認がすべて成功したら PR をマージしてください。リポジトリの保護設定を回避しないでください。
   ```

9. 処理の進行を確認し、報告された阻害要因に対処します。続行する前に、PR の状態が **Merged** であることを確認します。マージ権限を有効にしたことやエージェントが動作中であることは、マージ完了の確認にはなりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護や権限不足を回避しません。続行する前に阻害要因を解決してください。
