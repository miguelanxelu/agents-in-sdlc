アプリケーションの簡単な更新でも、複数のファイルを変更し、テストを実行する必要がある場合があります。開発者は通常、必要なファイルを探し、変更し、テストを実行し、デバッグし、変更漏れのファイルを見つけて再度更新します。これを何度も繰り返すことになります。

このような作業に役立つのが Copilot エージェントモードです。

Copilot エージェントモードは、IDE 内でより自律的に作業します。開発者と同様に、既存のプロジェクト構成を調べ、必要な変更を行い、テストなどのタスクを実行し、見つかった問題を自動的に修正します。エージェントモードでサイトに機能を追加する方法を確認しましょう。

> [!NOTE]
> 名前は似ていますが、エージェントモードと cloud agent は異なる用途向けです。エージェントモードは IDE 内で動作し、すばやいフィードバックと対話を可能にします。cloud agent はチームメンバーのように非同期で作業し、issue とプルリクエストを通じてやりとりします。

この演習では、次の内容を学びます。

- Copilot エージェントモードがプロジェクトを調べ、関連ファイルを特定し、複数のファイルを連携して変更する方法。
- GitHub Copilot エージェントモードで UI とデータ層にまたがる機能を実装する方法。
- コードベースにマージする前に、Copilot エージェントモードが生成した変更とテストをレビューする方法。

## シナリオ

ゲームの一覧が増えてきたため、カテゴリと発行元で絞り込めるようにします。前の演習で発行元ヘルパーを追加しました。今回は Copilot エージェントモードを使い、残りのデータ層、UI、テストを仕上げます。

## Tailspin Toys Web サイトを実行する

変更を加える前に、現在の機能を把握するため Tailspin Toys Web サイトを確認します。

Tailspin Toys は、開発者をテーマにしたボードゲームのクラウドファンディングプラットフォームです。ゲームの一覧と詳細を表示します。サイトは単一の Astro アプリで、ビルド時にページを静的 HTML として生成します。ページは frontmatter 内で Drizzle ORM を使ってローカルの SQLite データベースを直接照会します。別のバックエンド API やクライアント側 UI フレームワークはありません。再利用可能なデータアクセスヘルパーは `src/lib/` にあり、インタラクティブな機能は標準 DOM API を使う小さな Astro `<script>` で追加します。

### Web サイトを起動する

サイトを簡単に実行できるよう、単一の Astro 開発サーバーを起動する `npm run dev` タスクが用意されています。GitHub Codespace で次の手順を実行します。

1. Codespace に戻ります。前の演習を終えていれば、`main` に戻っているはずです。
2. <kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押して、Codespace 内に新しいターミナルを開きます。
3. フィルター機能の新しいブランチを作成して切り替えます。

   ```bash
   git checkout main
   git pull
   git checkout -b filtering-vscode
   ```

4. 次のコマンドで Web サイトを起動します。

   ```bash
   npm run dev
   ```

   Astro 開発サーバーの準備ができると、次のような URL を含むバナーが表示されます。

   ```bash
   🚀 Tailspin Toys is ready!
      Astro server: http://localhost:4321
      Press Ctrl-C to stop.
   ```

> [!NOTE]
> `http://localhost:4321` を開くよう促すダイアログが表示された場合は、**x** を選択して閉じます。

5. <kbd>Command</kbd> (Mac) または <kbd>Ctrl</kbd> (Windows/Linux) を押しながら、ターミナルに表示された Astro サーバーのアドレス `http://localhost:4321` を選択してサイトを開きます。

> [!NOTE]
> Codespace のターミナルで localhost の URL を選択すると、自動的に `https://<your-codespace-name>-4321.app.github.dev/` にリダイレクトされます。これは Codespace 内で Web サーバーをホストするためのプライベートトンネルです。

### Web サイトを確認する

Web サイトが起動したら、現在の機能を確認します。主な機能は次のとおりです。

- **ホームページ**: ボードゲームのタイトル、画像、説明を一覧表示します。
- **ゲーム詳細ページ**: ゲームを選択すると、タイトル、説明、発行元、カテゴリなどの詳細を表示します。

## Copilot でバックログを確認する

> [!TIP]
> **Copilot Chat を開く**
>
> 以下の演習を始める前に、Codespace に戻って Copilot Chat パネルを開き、**New Chat** を選択して新しい会話を開始します。モードとモデルの選択は演習によって異なります。必要な箇所で説明します。

サイトの初期実装は動作しますが、新しい機能を追加します。まずバックログを確認します。テンプレートからプロジェクトをセットアップしたときに issue が自動作成されています。GitHub Copilot にそれらを表示してもらいます。

1. Chat ビューのエージェント選択メニューから **Agent** を選びます。**Agent** はファイル間の変更を自律的に計画・実装し、ターミナルコマンドを実行してツールを呼び出します。

   ![Chat ビューのエージェント選択メニューのスクリーンショット](../../../_images/shared-chat-mode-selector.png)

2. 利用可能なモデル一覧から **Claude Sonnet 4.5** を選択します。

> [!CAUTION]
> このワークショップは、特定のモデルを推奨するものではありません。作成時に Claude Sonnet 4.5 を使用したため、手順にも記載しています。提案の一貫性を高め、円滑に進めるためですが、大規模言語モデル (LLM) は確率的に動作するため、提案は記載内容と異なる場合があります。これは通常の動作です。

> [!NOTE]
> LLM の確率的な性質により、Copilot が別の MCP コマンドを使用する場合がありますが、タスクは完了できるはずです。

3. 次のプロンプトを Copilot に送信して、バックログを確認します。

   ```plaintext
   GitHub リポジトリのバックログを表示してください。ユーザーに最も役立つ項目を基に、優先順位を付けてください。
   ```

4. **Continue** を選択して、すべての issue を一覧表示するコマンドを実行します。
5. 生成された issue の一覧を確認します。

Copilot がユーザーに最も役立つと思われる順に issue を優先付けしたことを確認します。

## 指示ファイルを確認する

コードの生成をエージェントに依頼する前に、Copilot にコンテキストを与える指示ファイルを確認します。Web サイトに機能を追加する方法を示す [ユーザーインターフェイス (UI) の指示ファイル](https://github.com/github-samples/tailspin-toys/blob/main/.github/instructions/ui.instructions.md)を使います。

1. Codespace で `.github/instructions/ui.instructions.md` を開きます。
2. 機能追加に関する全体的な指針を確認します。アーキテクチャの概要、コンポーネントの設計、テスト容易性、アクセシビリティの原則、次のファイル種別に関する指示へのリンクが含まれています。
   - Astro
   - Tailwind CSS
   - Drizzle

> [!TIP]
> 指示ファイルから、他の指示ファイルやプロジェクト内のファイルを参照できます。パスは指示ファイルの場所を基準とします。これにより、指示の再利用、複雑な内容の分割、コード生成の参考となる例やテンプレートの指定ができます。

## フィルター機能を実装する

フィルター機能を完成させるには、少なくとも次の3種類の変更が必要です。

- データ層 (`src/lib/`) のフィルターロジックを追加または調整します。
- フィルターの動作を確認するテストを追加または更新します。
- ゲーム一覧ページにフィルター UI を追加します。

さらに、コードベースにマージする前にテストを実行し、成功させる必要があります。Copilot エージェントモードにこれらの作業を依頼します。

1. 現在の Copilot の会話を続けるか、**New Chat** を選択して新しい会話を開始します。
2. **Add Context**、**Instructions**、**ui** の順に選択し、UI 指示ファイルを追加します。

   ![UI 指示ファイルを選択する例のスクリーンショット](../../../_images/ex3-select-instructions-file.png)

3. Chat ビューのエージェント選択メニューで、引き続き **Agent** が選択されていることを確認します。

   ![Chat ビューのエージェント選択メニューのスクリーンショット](../../../_images/shared-chat-mode-selector.png)

4. モデルが引き続き **Claude Sonnet 4.5** であることを確認します。
5. バックログ内の関連 issue に基づいて機能を実装するよう、次のプロンプトで Copilot に依頼します。

   ```plaintext
   バックログにある関連 GitHub issue の要件に基づいて、発行元とカテゴリによる絞り込みをサイトに追加してください。前の演習で発行元ヘルパーを作成済みです。必要に応じてその作業を維持・改善しながら、残りのデータ層、UI、テストを完成させてください。完了前にすべてのテストが成功することを確認してください。サーバーはすでに実行中なので、起動する必要はありません。
   ```

6. Copilot がプロジェクトを調べ、目的の機能に関連するファイルを探してから変更とテストを行う様子を確認します。データ層のヘルパー、UI、テストを探し、ファイルの変更とテストの実行に進みます。

   ![Copilot がプロジェクトファイルを調べている様子のスクリーンショット](../../../_images/ex3-agent-mode-explores.png)

> [!NOTE]
> Copilot はプロジェクトの調査、ファイルの変更、テストの実行などを行うため、タスクの複雑さやコードベースによって数分かかる場合があります。作業中は、コードエディターに **Keep** と **Undo** が表示されることがあります。Copilot が完了すると、すべての変更に **Keep** または **Undo** が表示されます。作業中に選択する必要はありません。

7. Copilot に促されたら **Continue** を選択してテストを実行します。

   ![Copilot Chat のペインでテスト実行の確認を求めるダイアログのスクリーンショット](../../../_images/ex3-agent-mode-run-tests.png)

8. 作業中に一時停止したり、テストが失敗したりする場合があります。問題ありません。Copilot はコード生成とテストを繰り返し、タスクを完了してエラーがないと判断するまで作業します。

   ![Copilot エージェントモードの完了した Chat セッションのスクリーンショット](../../../_images/ex3-agent-mode-proposed-changes.png)

9. 生成されたコードに問題がないか確認します。

> [!CAUTION]
> Copilot などの AI ツールが生成したコードは、必ずレビューしてください。

10. Web サイトを実行しているブラウザーに戻り、新しい機能を確認します。
11. すべてが動作し、コードのレビューも終わったら、Copilot Chat ウィンドウで **Keep** を選択します。

## まとめと次のステップ

GitHub Copilot エージェントモードを使って、Tailspin Toys Web サイトに機能を追加しました。この演習では、次の方法を確認しました。

- GitHub Copilot エージェントモードで UI とデータ層にまたがる新機能を実装する。
- プロジェクトを調べて関連ファイルを見つけ、連携して変更する。
- コードベースにマージする前に、生成された変更とテストをレビューする。

### 追加の演習 - ページングを実装する

ゲームの一覧が増えるにつれて、ページングが必要になります。この演習で学んだ方法を使って、Copilot にサイトのページングを依頼します。

- 既存の指示ファイルを使うなど、現在のベストプラクティスに従います。
- ページサイズをユーザーが選べるようにするか、固定にするかを検討します。
- 希望どおりの実装に必要な情報をプロンプトに含めます。
- Copilot に変更を求めたりコンテキストを追加したりして、何度か反復する場合があります。これは Copilot を使うときの通常の流れです。
