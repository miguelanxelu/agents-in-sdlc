ワークスペースを確認し、クイックチャットも試しました。次は**エージェントセッション**を開始し、プロジェクトに最初の変更を加えます。変更は小さくします。ゲームのデータには星評価がありますが、ホームページのゲームカードにはまだ表示されていません。エージェントに表示を依頼し、変更をレビューして、最初のプルリクエストとしてマージします。

このレッスンでは、次の作業を行います。

- エージェントセッションを開始し、セッションの構成を確認します。
- エージェントに対象を絞った小さな変更を依頼します。
- ワークスペースの差分ビューで変更をレビューします。
- アプリをローカルで実行し、ブラウザーで変更を確認します。
- 最初のプルリクエストを作成してマージします。

## シナリオ

Tailspin Toys の各ゲームには星評価があり、ゲーム詳細ページにはすでに表示されています。一方、ホームページのゲームカードにはタイトル、カテゴリ、発行元、説明しか表示されていません。最初のセッションの練習として、各カードに既存の評価を表示するようエージェントに依頼します。小さく自己完結した変更なので、最初のセッションに適しています。

## セッションの構造

**セッション**は、独立したワークスペースで動くエージェントとの会話です。各セッションには**専用の Git worktree とブランチ**が割り当てられます。そのため、一方のセッションで機能を追加しながら、別のセッションでバグを修正しても変更が競合しません。セッションはサイドバーでリポジトリごとにまとめられています。セッションを選択すると切り替えられます。

セッションには、エージェントとの**会話**、ファイルを調査・編集するときの**ツール操作**、差分とともに表示される**変更ファイル一覧**があります。

## セッションを開始して変更を依頼する

新しいセッションでプロジェクトを調べ、機能を実装します。[アプリのセットアップ][prior-lesson]で GitHub リポジトリからプロジェクトを追加しました。そのリポジトリ用のセッションを作成して、変更を依頼します。

1. GitHub Copilot app に戻ります。アプリを閉じている場合は開きます。
2. サイドバー上部の **+** を選択してセッションを開始します。
3. リポジトリとして `tailspin-toys` を選択します。
4. プロンプトボックスの下で **new working tree** と **Interactive** モードを選び、次のプロンプトを送信します。

   ```plaintext
   一覧ページのゲームカードに、各ゲームの `starRating` を5段階で表示してください。評価が null の場合は "No rating yet" と表示してください。カードのレイアウトはそのままにし、テストを追加して、関連するチェックを実行してください。
   ```

5. <kbd>Enter</kbd> を押して、プロンプトを Copilot に送信します。

Copilot app は最初にプロジェクトの分離されたコピーである新しい worktree を作成します。次にプロジェクトを調べ、新機能に必要なファイルを見つけてコードを作成します。Copilot app を使って新機能を追加できました。

## 差分をレビューする

AI が生成した変更は、どれほど小さくてもマージ前にレビューします。Copilot app で変更を確認します。

1. アプリの右上にある **Toggle review panel** を選択します。開いたパネルで **Changes** を選ぶと、変更されたファイルと差分が表示されます。

   ![Create PR の右側にある Toggle review panel ボタンを矢印で示した GitHub Copilot app の上部ツールバー](../../../_images/app-2-review-panel.png)

2. ゲームカードを表示する中心的なファイル `GameCard.astro` にコードが追加されていることを確認します。評価がある場合は表示し、`starRating` が `null` の場合は "No rating yet" と表示する次のようなコードです。

   ```astro
   {game.starRating !== null ? (
       <span class="text-xs font-medium px-2.5 py-0.5 rounded bg-amber-900/60 text-amber-300" data-testid="game-rating">
           ★ {game.starRating} / 5
       </span>
   ) : (
       <span class="text-xs font-medium text-slate-500" data-testid="game-rating-empty">
           No rating yet
       </span>
   )}
   ```

> [!NOTE]
> Copilot を含む生成 AI ツールは確率的に動作するため、コードは上記と異なる場合があります。大まかな構造が似ていることを確認してください。

## 変更を確認する

ブラウザーを開く前に、エージェントの自動チェック結果をレビューします。数値の `starRating` と、`null` の場合の代替表示がテストされていることを確認してください。前提条件が不足していたり、チェックがスキップされていたりする場合は成功ではありません。インストールの要求は内容を確認してから承認します。

コードを読むだけで動くと判断せず、Copilot に Web サイトを起動させ、更新されたユーザーインターフェイス (UI) を確認します。組み込みのブラウザーキャンバスで開きます。

> [!TIP]
> キャンバスは Copilot app 内で使えるインタラクティブなウィジェットです。後のレッスンでカスタムキャンバスを調べ、自分でも作成します。ここでは組み込みのブラウザーキャンバスを使います。

1. 次のプロンプトで、アプリを起動してブラウザーキャンバスで開くよう Copilot に依頼します。

   ```plaintext
   アプリを起動し、ブラウザーキャンバスで開いてください。
   ```

2. しばらくするとアプリが起動し、Copilot app 内にブラウザーウィンドウが開きます。
3. 評価があるゲームカードに5点満点の値が表示されることを確認します。
4. 確認が終わったら、次のプロンプトで、このセッションで起動した開発サーバーを停止するよう Copilot に依頼します。

   ```plaintext
   開発サーバーを停止し、ブラウザーキャンバスを閉じてください。
   ```

## 最初のプルリクエストを作成してマージする

機能を作成できました。次に、新しいコードを既存のコードベースにマージするためのプルリクエスト (PR) を作成します。

1. 右上隅にある **Create PR** を選択します。
2. 求められた場合は **Sign in with your browser** を選択し、画面の指示に従って認証します。
3. Copilot が、PR の作成前に対応する issue が必要というリポジトリポリシーを説明した場合は、その手順に従うよう確認します。
4. Copilot が PR を作成するまで待ちます。
5. チャットのすぐ上にある **PR** バブルを選択し、レビューペインで PR を開きます。ここで PR をレビューできます。
6. 準備ができたら **Ready to merge** を選択します。
7. 表示されたダイアログで **Merge pull request** を選択して、PR をマージします。

## まとめと次のステップ

GitHub Copilot app を使って最初の変更を公開しました。次の作業を行いました。

- エージェントセッションを開始し、セッションの構成を確認しました。
- エージェントにゲームカードの対象を絞った小さな変更を依頼しました。
- ワークスペースの差分ビューで変更をレビューしました。
- アプリをローカルで実行し、ブラウザーで星評価を確認しました。
- PR 1 を作成し、チェックをレビューして、自分でマージしました。
